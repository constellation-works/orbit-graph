# Warm navigation v1 (proposed)

This is a prospective capability, not a measured study or evidence that graph
navigation helps. Admission awaits the root's cold measurement priorities,
independent review, strict host qualification and actual-client rehearsal.
Fixtures and scripted results here are test-only. Never relabel cold captures.

Request schema 5 / runner 8 / installed-plugin-warm-batch-v1 uses the current
shared runner, broker, safe-tool-text-v1 and schema-3 telemetry. Schemas 1–3
remain cold; schema 4 remains one-shot-patch-v1. Version all changes to this
profile's state, schedule, controls or scoring interpretation before output.

Freeze before any study output: independent source commits and full permitted
source exports, ordered task prompts and rubric lock, plugin/skill/inventory/
backend/host digests, model/version/settings/provider binary, baseline binaries,
sandbox/resource bounds, helper and protocol/evaluator hashes, state policy and
ABBA or BAAB batch order. Every paired slot has the same source and two-commit
Git visibility, question, budgets and controls. The graph receives unchanged
shipped skill and inventory. Graph use remains observed model choice; never
insert sync/warmup calls into a real model script. Test scripts deliberately
exercise sync and invalidation and establish no usage frequency.

Each frozen contract file reserves each batch index once in an adjacent exclusive
admission receipt before installation. Do not copy/re-export the same study to
replace an outcome; receipts and incomplete outputs are retained.

Each of four batches begins with empty private product state and a fresh output
path. Only its private repository .orbit, .orbit-graph and installed Orbit home
survive within that batch. Orbit-generated client skill links may point only
into that private installed root; external, dangling and undeclared links refuse.
Host-generated defaults and registry/database state under the private home are
manifested, not imported from a live host. Every slot receives a fresh source/Git
view, ephemeral model invocation, runtime, provider/broker logs, HOME, CODEX_HOME
and temporary directory. Installation assets and model context stay identical.
The host's own product logs are manifested inside private Orbit state; they are
not provider memory and the broker never exposes them. No batches share state.

Record the original schedule before executing its first slot. Each attempted
slot retains a checkpoint, source and request identities, before/after state
manifests, outcome and original partial or complete capture. Integrity refusals
stop further state reuse; later slots remain scheduled and explicitly not_run.
Provider failures that leave supervised product state intact do not erase later
slots. Cancellation terminates and reaps the provider through the shared runner,
then leaves the rest unrun. No retries, replacement outcomes, selective warmup,
dropped initial tasks or resume into a previous output directory are allowed.
For SIGKILL or host loss the original schedule/checkpoints remain evidence of
an incomplete batch; absence of batch.json refuses completed-batch replay.

The minimal qualification schedule is unchanged source, unchanged source, then
one independently committed edit. Query stale state, synchronize by observed
choice, and compare incremental results to a separate empty-state batch at the
edited source. Preserve source/extractor/store/history/plugin schema identity,
backend and state file hashes, sync attempt ledgers and original product index
facts. Repeated invocation is insufficient to prove a cache hit. This profile
reports product cache outcome unknown; it never labels a hit from warm state.

A batch's single monotonic interval starts at admission, before identity probes,
preflights, private installation, initial indexing and every scheduled attempt;
it ends after slot checkpoints and final state inventory, before writing the
sealed summary. Slot intervals are nonoverlapping subintervals. Per-task phase
clocks remain nested diagnostics and are never summed into the batch wall.
Original source export and qualification costs outside the batch remain separate
nullable observations; never charge those twice. Cohort replay requires all four
batches in frozen chronological order with nonoverlapping walls. OS page cache
is uncontrolled; order counterbalancing limits order bias, not cache equivalence.
No cache flushing or selective prewarming is performed. Report the limitation.

Primary outcomes are all-attempt exact answer-set accuracy with source-checked
citations, measured batch wall and measured tool output bytes. Amortized batch
wall divides by ALL scheduled slots, including refusals, failures and not_run.
Tool output bytes, installation output bytes and identity-probe output bytes
are separate components. Shared provider preflight and version-probe wire byte
totals are unavailable, so the whole-batch tool-byte total stays null; a separate
partial observation includes captured model/installation/identity-probe bytes.
The model tool-output total is available only with complete slot coverage.
Missing coverage has a null total plus a separately named partial observation.
Preserve per-field usage, failed/missing turns, unqualified scope/cache semantics
and overlapping phases verbatim. Never synthesize total tokens, input+output,
uncached inputs, aggregate session totals, model prices or cost.

Seals attest producer consistency and detect drift, not authenticity against a
same-user producer capable of resealing all evidence. Diagnostic containment none
is an accident guard, never a security boundary or effectiveness evidence. Strict
admission requires the real sandbox and finite memory/process ceilings; test
success or a nested namespace denial cannot stand in for it.
